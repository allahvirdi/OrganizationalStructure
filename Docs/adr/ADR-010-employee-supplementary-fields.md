# ADR-010: فیلدهای تکمیلی پرسنل (تاریخ تولد، سابقه حراست، موبایل پژواک)

- **وضعیت:** Accepted
- **تاریخ:** 2026-09-14
- **نویسنده:** Technical Lead / Domain (تأیید کارفرما)

## Context
پس از انجماد مدل دامنه در Phase 2، کارفرما سه فیلد تکمیلی برای پرسنل درخواست کرد: تاریخ تولد، سابقه حراست (به شکل «۱۲ سال و ۳ ماه») و شماره موبایل پژواک. همچنین DEC-022 (عدم حذف فیزیکی پرسنل) ثبت شد. تغییر مدل منجمد فقط با ADR مجاز است.

## Decision
- `BirthDate` (DateOnly، اختیاری) — PII با رمزنگاری **Randomized** (فقط نمایشی/گزارشی، نه کلید جستجو).
- `PezhwakMobile` (رشته، اختیاری) — PII با رمزنگاری **Deterministic** (مشابه Mobile: شناسه قابل جستجو).
- `HerasatServiceRecord` (Value Object اختیاری: `Years ≥ 0` + `Months 0..11`) — **غیر PII** (مدت خدمت، غیر هویتی)؛ به‌صورت Owned ذخیره می‌شود.
- متد `UpdateSupplementaryInfo` برای ویرایش هر سه فیلد با رویداد `EmployeeUpdated`؛ سازنده `Create` با پارامترهای اختیاری سازگاربه‌عقب گسترش می‌یابد.
- طبقه‌بندی PII فوق بر اساس سیاست ADR-006 است؛ بازنگری توسط Security Lead مجاز است (بدون نیاز به ADR جدید، فقط ثبت در ChangeLog).

## Rationale
- پوشش نیاز کسب‌وکار بدون شکستن قراردادهای موجود (پارامترهای اختیاری).
- تفکیک PII از غیر-PII مطابق سیاست مصوب؛ حداقل‌سازی سطح رمزنگاری.

## Considered and rejected alternatives
- جدول جدای سوابق خدمت: رد شد — برای MVP بیش از نیاز است؛ در صورت نیاز آینده با ADR اضافه می‌شود.
- عدم برچسب PII برای تاریخ تولد: رد شد — تاریخ تولد داده حساس است.

## Consequences
- مثبت: مدل کامل‌تر بدون شکست سازگاری.
- منفی: پیاده‌سازی رمزنگاری دو نوع جدید در Phase 3 (EF Config).

# ADR-006: حفاظت از داده‌های حساس پرسنلی (PII) — Always Encrypted

- **وضعیت:** Accepted
- **تاریخ:** 2026-09-14
- **نویسنده:** Security Lead / Technical Lead (تأیید کارفرما)

## Context
این سامانه مالک اطلاعات کامل پرسنلی است که شامل داده‌های حساس هویتی/پرسنلی است. کارفرما استفاده از **الگوی Always Encrypted مطابق ADR-004 پروژه خواهر** را تأیید کرد. سند امنیتی مستقلی در Repository این پروژه وجود ندارد؛ بنابراین مرجع، الگوی پروژه خواهر و Security Baseline است.

## Decision
- فیلدهای حساس PII هنگام ذخیره‌سازی **رمزنگاری میشوند (Always Encrypted)**.
- نوع رمزنگاری: **Deterministic** برای فیلدهای جستجوپذیر/یکتا (کد ملی، شناسه‌های جستجویی) و **Randomized** برای فیلدهای متنی آزاد (نام، نام خانوادگی و مشابه).
- **عدم ثبت PII در لاگ‌ها**؛ استفاده از شناسه‌های مرجع به‌جای مقادیر حساس.
- ستون‌های Audit و Soft Delete برای تمام جداول اصلی.
- دسترسی به PII فقط با احراز هویت + تصریح‌دهی معتبر (Deny by Default).
- عدم بازگشت PII در پاسخ‌های غیرضروری.
- سیاست نگهداری/حذف PII به‌عنوان سؤال باز ثبت شده و پس از تصمیم اعمال میشود (Q-005).

## Rationale
- ماهیت حساس داده‌های پرسنلی و الزام امنیتی کارفرما.
- یکنواختی با الگوی رمزنگاری پروژه خواهر و زیرساخت IAM (که نیز Always Encrypted دارد).
- کاهش ریسک نشت داده.

## Considered and rejected alternatives
- ذخیره متن ساده PII: رد شد — ریسک نشت و عدم انطباق.
- TDE به‌تنهایی: کافی نیست؛ به‌صورت مکمل در لایه داده اعمال میشود.
- رمزنگاری کامل کل پایگاه‌داده: رد شد — اثر عملکردی و پیچیدگی جستجو.

## Consequences
- مثبت: کاهش ریسک نشت و انطباق با الزام حریم خصوصی.
- منفی: پیچیدگی جستجو روی فیلدهای Randomized (نیاز به ستون هش جستجویی)؛ هزینه محاسباتی اندک.
- نیازمند تصمیم تکمیلی: سیاست نگهداری و حذف PII (Q-005).

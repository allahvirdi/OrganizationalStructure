# API Contract — Import (ورود ساختار سازمانی از فایل)

**نسخه:** `v1`
**پیشوند:** `/api/v1/import`
**وضعیت:** پیاده‌شده (ساختار پست‌ها + پرسنل)
**تصریح‌دهی:**
- مسیر پست‌ها: احراز هویت + `OrganizationStructure.Post.Create` (چون ماهیت عملیات ایجاد پست است؛ مجوز جدید نیازمند ثبت در IAM است و فعلاً از مجوز موجود استفاده می‌شود — کاتالوگ ۲۷تایی حفظ شد)
- مسیر پرسنل: احراز هویت + `OrganizationStructure.Employee.Import` (مصوب DEC-025؛ تا زمان ثبت در IAM همه درخواست‌ها ۴۰۳ می‌گیرند — رفتار Deny by Default)

---

## دامنه

- بارگذاری ساختار سازمانی (پست‌ها) از فایل اکسل (`.xlsx`) برای یک سازمان مشخص.
- هر ردیف یک پست است؛ سلسله‌مراتب با «کد پست والد» در همان فایل ساخته می‌شود.
- فایل نامعتبر یا حاوی خطا → کل عملیات رد می‌شود (Atomic).

---

## قالب فایل اکسل

| ستون | هدر فارسی | اجباری | توضیح |
|------|-----------|--------|-------|
| A | کد پست | بله | کد یکتا درون سازمان (حداکثر ۵۰ کاراکتر) |
| B | عنوان پست | بله | عنوان پست (حداکثر ۲۰۰ کاراکتر) |
| C | شرح | خیر | شرح اختیاری (حداکثر ۱۰۰۰ کاراکتر) |
| D | کد پست والد | خیر | کد پست والد در **همین فایل** یا پست‌های موجود؛ خالی یعنی ریشه |

### قوانین اعتبارسنجی
- ردیف اول باید هدر باشد (ترتیب ستون‌ها مهم است).
- کد پست نباید تکراری باشد (نه در فایل، نه در دیتابیس سازمان).
- کد پست والد باید یا در فایل وجود داشته باشد یا از قبل در دیتابیس ثبت شده باشد.
- حداکثر ۵۰۰ ردیف در هر بارگذاری.
- فرمت فایل فقط `.xlsx` مجاز است.
- حداکثر حجم فایل: ۵ مگابایت.

## Endpointها

### بارگذاری ساختار سازمانی — `POST /api/v1/import/posts`

**Content-Type:** `multipart/form-data`

| پارامتر | نوع | توضیح |
|---------|-----|-------|
| `organizationId` | GUID (form-data) | سازمان مقصد (باید در محدوده کاربر باشد) |
| `file` | File (form-data) | فایل اکسل `.xlsx` |

**پاسخ موفق:** `201 Created`
```json
{
  "importedCount": 15,
  "organizationId": "3fa85f64-..."
}
```

**پاسخ خطا:**

| کد خطا | وضعیت | توضیح |
|--------|-------|-------|
| `Import.InvalidFile` | 400 | فایل خالی، فرمت نادرست، یا بدون ردیف داده |
| `Import.DuplicateCodeInFile` | 400 | کد تکراری در فایل |
| `Import.ParentNotFound` | 400 | کد والد در فایل و دیتابیس یافت نشد |
| `Import.RowLimitExceeded` | 400 | بیش از ۵۰۰ ردیف |
| `Post.DuplicateCode` | 409 | کد در دیتابیس سازمان وجود دارد |
| `Access.Forbidden` | 403 | سازمان خارج از محدوده کاربر |
| `Validation.Failed` | 400 | خطای اعتبارسنجی فیلدها |

---

### دانلود قالب نمونه — `GET /api/v1/import/posts/template`

**پاسخ:** فایل اکسل `.xlsx` با هدر فارسی و یک ردیف نمونه.

| هدر | مقدار نمونه |
|-----|-------------|
| کد پست | MGR-001 |
| عنوان پست | مدیرعامل |
| شرح | بالاترین سطح مدیریتی |
| کد پست والد | |

## ورود دسته‌جمعی پرسنل

- بارگذاری اطلاعات پرسنلی یک سازمان از فایل اکسل (`.xlsx`) یا CSV (UTF-8) برای یک سازمان مشخص.
- هر ردیف یک پرسنل است؛ `userId` (اتصال به IAM) در این مسیر پشتیبانی نمی‌شود و خالی ثبت می‌گردد.
- فایل نامعتبر یا حاوی خطا → کل عملیات رد می‌شود (Atomic) و هیچ پرسنلی ثبت نمی‌شود.
- حداکثر ۵۰۰ ردیف و ۵ مگابایت (مشابه مسیر پست‌ها).

### قالب فایل (اکسل و CSV — ترتیب ستون‌ها الزامی)

| ستون | هدر فارسی | اجباری | توضیح |
|------|-----------|--------|-------|
| A | کد پرسنلی | بله | دقیقاً ۸ رقم؛ یکتا در سطح مستأجر |
| B | نام | بله | حداکثر ۲۰۰ کاراکتر |
| C | نام خانوادگی | بله | حداکثر ۲۰۰ کاراکتر |
| D | کد ملی | بله | ۱۰ رقم معتبر (کنترل‌رقمی) |
| E | موبایل | بله | `^09[0-9]{9}$` |
| F | تاریخ تولد (شمسی) | خیر | `yyyy/MM/dd` با ارقام فارسی یا لاتین |
| G | سال سابقه | خیر | عدد نامنفی؛ باید با ماه سابقه همراه باشد |
| H | ماه سابقه | خیر | ۰ تا ۱۱؛ باید با سال سابقه همراه باشد |
| I | موبایل پژواک | خیر | `^09[0-9]{9}$` |

### قوانین اعتبارسنجی
- ردیف اول هدر است؛ ردیف‌های کاملاً خالی نادیده گرفته می‌شوند.
- تکراری بودن کد پرسنلی یا کد ملی **در فایل** → ۴۰۰ (کد ملی در پیام خطا افشا نمی‌شود).
- وجود کد پرسنلی **در دیتابیس** → ۴۰۹ `Employee.DuplicatePersonnelCode`.
- ارقام فارسی/عربی، نیم‌فاصله و جداکننده هزارگان به‌صورت شفاف نرمال‌سازی می‌شوند.
- تاریخ تولد شمسی به میلادی تبدیل و به‌صورت `DateOnly` ذخیره می‌شود.
- `PezhvakIsActive` در این مسیر ورودی ندارد و `null` (تعیین‌نشده) می‌ماند؛ تعیین آن از مسیر ویرایش تکمیلی انجام می‌شود.
- CSV باید UTF-8 باشد (BOM مجاز و در قالب تولیدشده وجود دارد) و از نقل‌قول‌دوتایی RFC 4180 پشتیبانی می‌شود.

### بارگذاری پرسنل — `POST /api/v1/import/employees`

**Content-Type:** `multipart/form-data`

| پارامتر | نوع | توضیح |
|---------|-----|-------|
| `organizationId` | GUID (form-data) | سازمان مقصد (باید در محدوده کاربر باشد) |
| `file` | File (form-data) | فایل `.xlsx` یا `.csv` |

**پاسخ موفق:** `201 Created`
```json
{
  "organizationId": "3fa85f64-...",
  "importedCount": 42
}
```

**پاسخ خطا:**

| کد خطا | وضعیت | توضیح |
|--------|-------|-------|
| `Import.InvalidFile` | 400 | فایل خالی/آسیب‌دیده، پسوند نامعتبر، هدر ناقص یا بدون ردیف داده |
| `Import.EmployeeRowInvalid` | 400 | خطای فیلد یک ردیف (به همراه شماره ردیف، بدون افشای مقادیر PII) |
| `Import.DuplicatePersonnelCodeInFile` | 400 | کد پرسنلی تکراری در فایل |
| `Import.DuplicateNationalCodeInFile` | 400 | کد ملی تکراری در فایل |
| `Import.RowLimitExceeded` | 400 | بیش از ۵۰۰ ردیف |
| `Employee.DuplicatePersonnelCode` | 409 | کد پرسنلی در دیتابیس وجود دارد |
| `Access.Forbidden` | 403 | سازمان خارج از محدوده کاربر یا نداشتن مجوز |

### دانلود قالب پرسنل — `GET /api/v1/import/employees/template?format=xlsx|csv`

**پارامتر:** `format` (پیش‌فرض `xlsx`)؛ `csv` فایل UTF-8 با BOM و هدر فارسی برمی‌گرداند.
**پاسخ:** فایل قالب با دو ردیف نمونه (یکی کامل، یکی با ستون‌های اختیاری خالی).

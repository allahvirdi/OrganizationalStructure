# Ubiquitous Language — زبان یکپارچه دامنه

**آخرین به‌روزرسانی:** `2026-09-14`

> اصطلاحات استاندارد پروژه؛ باید در کد، API و اسناد به همین شکل استفاده شوند.

| اصطلاح | نام فنی | تعریف |
|--------|---------|-------|
| سازمان | `Organization` | واحد سازمانی مستقل که درخت Post خود را دارد؛ Master در IAM و اینجا Reference است. |
| پست سازمانی | `Post` | هر جایگاه در ساختار درختی؛ یک گره درخت. |
| پست بالادست | `ParentPost` | پست مستقیم بالادستی (حداکثر یک عدد). |
| پست پاییندست | `ChildPost` | پست(های) مستقیم پاییندستی (صفر یا چند عدد). |
| زیرشاخه | `Subtree / Descendants` | تمام پست‌های پاییندستی در چندین سطح. |
| کارمند / پرسنل | `Employee` | فرد دارای اطلاعات کامل پرسنلی در این دامنه؛ `≠ IAM User`. |
| انتساب پرسنل به پست | `EmployeePostAssignment` | رابطه تعیین‌شده بین یک Employee و یک Post (یک پرسنل می‌تواند چند Post داشته باشد). |
| مسئولیت | `Responsibility` | مسئولیت سازمانی ویژه‌ی یک Post. |
| صاحب امضا | `Signing Authority` | اختیار امضای یک Post؛ باید در چارت متمایز نمایش داده شود. |
| محدوده سازمانی | `Organization Scope` | محدوده مجاز مشاهده/مدیریت کاربر مبتنی بر ساختار و Permission. |
| مجوز | `Permission` | حق مشخص برای عملیات دامنه (`Post.Create`, `Employee.Read`, ...). |
| نقش | `Role` | مجموعه‌ای از Permissionها که در IAM تخصیص داده می‌شود. |
| فعال / غیرفعال | `Active / Inactive` | وضعیت چرخه حیات موجودیت‌ها؛ غیرفعال شدن به معنی حذف تاریخی نیست. |
| جدول واسط | `Staging Table` | جدول ورودی برای Import اطلاعات پرسنلی (Schema نهایی: Q-003). |

## قواعد زبانی کلیدی

- `Employee` و `Post` ذاتاً متفاوت هستند؛ یک پست جایگاه است و یک کارمند فرد.
- `Organization` در این پروژه همیشه به رنگ «Reference به IAM» شناخته می‌شود، نه موجودیت محلی Master.
- «مشاهده سلسله‌مراتبی» با «مشاهده روابط نزدیک (Parent/Child مستقیم)» متفاوت است.

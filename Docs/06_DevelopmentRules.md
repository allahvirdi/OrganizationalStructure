## ۱. قانون تایم‌باکس ۱۵ دقیقه‌ای (اجباری)

- هر تسک و هر زیرفاز حداکثر **۱۵ دقیقه** زمان‌بندی می‌شود.
- اگر تسکی بیشتر طول می‌کشد، باید به تسک‌های کوچک‌تر شکسته شود.
- قبل از شروع کار، لیست واحدهای ≤ ۱۵ دقیقه‌ای باید ارائه شود.
- بعد از اتمام هر واحد ۱۵ دقیقه‌ای، وضعیت گزارش و منتظر دستور بعدی می‌مانیم.

## ۲. قانون کامیت فقط بعد از تأیید صریح انسان (اجباری)

- هیچ کامیتی بدون تأیید مستقیم و صریح انسان مسئول زده نمی‌شود.
- بعد از هر تسک:
  1. خلاصه تغییرات گزارش شود
  2. لیست فایل‌های تغییرکرده اعلام شود
  3. صراحتاً درخواست تأیید برای کامیت داده شود
- فقط پس از تأیید صریح (مثلاً «تأیید شد» یا «کامیت بزن») کامیت انجام می‌شود.
- پیام کامیت باید واضح، مرتبط با تسک و شامل شناسه تسک باشد.

## ۳. مستندسازی کد (XML Documentation فارسی — اجباری)

- تمام Classها، Propertyها، Methodها و Interfaceها باید XML Documentation به **زبان فارسی** داشته باشند.
- هیچ عضوی بدون مستند فارسی پذیرفته نیست.

## ۴. ممنوعیت‌های کیفیت کد

هرگز تولید نشود:
- `TODO`
- `Mock` / `Fake` (مگر در پروژه تست)
- Sample Code
- Incomplete Code
- Comment اضافی و غیرمستند

## ۵. امنیت اجباری

- Authorization + Authentication (Deny by Default)
- Tenant Isolation
- Claim Validation
- OWASP Top 10
- XSS / CSRF / SQL Injection / IDOR / Path Traversal
- Secret Management (هیچ Secret در کد)
- HTTPS + Data Protection
- حفاظت PII (Always Encrypted) و عدم لاگ PII

## ۶. تست اجباری

- Unit Test + Integration Test برای هر قابلیت جدید
- Playwright در صورت نیاز

## ۷. قوانین Session

- قبل از هر خط کد: خواندن فایل‌های اجباری Docs
- فقط روی فاز اعلام‌شده کار شود
- در پایان Session: به‌روزرسانی `04_Progress.md` + `05_ChangeLog.md` + ایجاد Session Report
- قبل از خاتمه: اطمینان از قابلیت ادامه توسط AI/توسعهدهنده جدید بدون تاریخچه گفتگو

## ۸. قالب Frontend

- Frontend بر پایه استک Baseline (Next.js + MUI RTL + Tailwind) توسعه داده می‌شود (ADR-001).
- `SampleAdminPanel` فقط مرجع بصری/UX است، نه مرجع Domain/Architecture.
- تغییر Layout، Theme یا کامپوننت‌های پایه فقط با ADR مجاز است.
